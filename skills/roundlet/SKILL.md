Use when activating, operating, pausing, stopping, recovering, or auditing a single-repository Roundlet run.

# Roundlet

Operate a single-target-repository outer loop through Codex tasks, GitHub, Git worktrees, two advisory local files, and a read-only content-addressed contract snapshot. Do not introduce or depend on a Python runtime, database, executable validator, package, migration layer, runtime metrics, or cross-platform compatibility matrix.

## Preserve these invariants

- Use exactly one long-lived Orchestrator task, one phase-aware heartbeat, one authoritative machine, and at most one active leaf issue for a target repository.
- Pin every run at activation to an immutable content-addressed bundle under `.roundlet/contracts/<contract-id>/` containing this file, every required reference, the resolved role configuration, and a manifest of ordered paths and SHA-256 values. Read active-run instructions only from that bundle.
- A legacy run without an activation contract must first use the owner-authorized legacy bootstrap protocol to pin its exact activation-time source/ref and bytes. If that identity cannot be proven, stop; never seed the baseline from the current installed copy by assumption.
- Before activation, issue implementation, recovery, legacy bootstrap, or contract adoption/migration can cross its next Git/GitHub transition boundary, prove the exact advisory-state, linked-worktree, and linked-worktree-index mutation routes with unique bounded create/edit/read-back/cleanup canaries executed by the roles that will use them. Tool visibility or a zero-tool decision is not capability evidence.
- Create every activation or recovery Launcher directly against the target's exact authoritative checkout as its canonical current directory and normal writable local-project workspace before sending the metadata-only handshake. Independently read back that task/CWD/workspace binding and reject a projectless task, unrelated project, read-only route, or removable linked worktree before run reservation or mutation. A scoped approval cannot substitute for the required topology. This platform-neutral Launcher invariant does not generalize the separate native-Windows Worker anchor or empty-parent exception.
- Keep filesystem canaries platform-, shell-, and helper-neutral except for explicitly runtime-gated contracts. Retry an initial sandbox denial only through the narrowest host-supported approval path and only up to the configured limit. Require every shell wrapper to propagate the first failing Git/subprocess exit as a non-zero operation result; later output, formatting, or object construction must never mask it. Distinguish direct execution failure, explicit approval denial, unavailable approval, approved execution failure, and unproven filesystem capability; never infer one from another. If the advisory route itself cannot persist failed local evidence, retain only the bounded immutable task-response identity/digest and never treat it as accepted.
- Treat a Worker canary's `initial_index_sha256` as the exact raw index preimage, not only a semantic tree identity. Capture the resolved index bytes before any operation that may lock or write it, stage/inspect/unstage only the canary path, restore those exact bytes through the bounded Git-index route, and verify final raw-byte equality after all identity reads. Matching HEAD, status, tree, or entries never substitutes for the raw index hash, and no backup artifact may remain.
- Treat a changed installed skill or configuration as a candidate, never as live instructions. At clean `IDLE` with no leaf resources, require explicit allowlisted-owner authorization and the between-issue adoption protocol. In every other phase, require explicit authorization and the in-place migration protocol.
- Refuse activation when another live or unreconciled Roundlet run may own that target. The file lease is advisory and never prevents split-brain across machines, clones, or Codex tasks.
- Treat GitHub issues and pull requests as the durable backlog and audit history. Let only the Orchestrator mutate GitHub.
- Keep the same Worker task for initial implementation, repairs, the optional final repair, and cleanup preflight. Create a fresh read-only Supervisor task for every review attempt.
- On native Windows only, create every new Worker task in a dedicated host-owned task anchor whose canonical current directory is distinct from the Roundlet-owned removable linked worktree, and place that linked worktree at a separate writable descendant path. Never create a native-Windows Worker with its task current directory equal to or inside the removable worktree. Bind and verify both paths before canary or implementation. Require every Worker canary-artifact file create/change/delete and every source edit in its assigned writable worktree to use the dedicated `apply_patch` tool in the normal sandbox. Never route `apply_patch` through PowerShell, a pipeline, a here-string or here-document, a `.bat` or `.cmd` wrapper, or `require_escalated`. On this separated native-Windows topology, resolve whether the linked-worktree index and `index.lock` live outside the Worker's normal writable roots. Treat `git write-tree` and every other command that may create `index.lock` as part of the Git-index mutation route, not as a harmless identity read. If that exact out-of-root route is initially restricted, first prove and digest the initial absence of both canary files and their two exact immediate parents; that parent evidence cannot be reconstructed later. Then populate only the assignment values in the operator guide's native-Windows PowerShell body, parse the fully populated body before creating canary artifacts, and use that unchanged body as the sole narrowly approved compound operation bound to the exact worktree, resolved index, and canary path. It captures the raw preimage before its first potentially locking operation, performs initial identity reads plus stage/entry/blob/content verification, performs final identity reads, restores the captured bytes after those reads without a backup artifact, then verifies final raw length/SHA-256 and no `index.lock`. Never create an artifact after an absence/preflight or parse failure, consume the retry on a preliminary locking identity command, rewrite the template, or request a second approval. After `apply_patch` has removed every canary file, the only other native-Windows exception is the operator guide's two-turn empty-parent finalization: the external creator may remove only the exact canary-created, initially absent, ordinary, non-reparse, proven-empty parent with a nonrecursive, non-force exact-path directory operation; the same metadata-verified Worker must then prove absence on a fresh read-only finalization turn before returning `cleanup: VERIFIED`. These exceptions never permit file deletion, source mutation, worktree/anchor/run-state removal, target broadening, or reuse on WSL or a non-Windows host. If the separated writable topology, dedicated file route, exact compound index route, external empty-directory route, or final read-back is unavailable, fail closed as `FILESYSTEM_CAPABILITY_UNAVAILABLE`; do not retry a file mutation through an elevated shell. This conditional guard does not apply to WSL or non-Windows hosts and does not prohibit scoped elevation for genuinely host-bound GitHub, network, or the exact out-of-root Git-index operation.
- Bind every non-canary Worker and Supervisor turn to explicit issue, pull-request, phase, review epoch/round, and full commit SHA context plus its immutable `role_task`, exact populated `metadata_turn`, and execution profile. Bind every canary turn to the canary-specific phase, role/task/profile, runtime, exact checkout/worktree/route, initial identities, targets, and the contract/leaf resources that actually exist; use the defined `none-before-contract`, `none-before-legacy-contract`, `none-for-benchmark`, or `none` values only for genuinely pre-activation-contract, legacy-pre-contract, standalone-benchmark, or leafless phases. Bind every canary result to the task-metadata-verified exact `model=<id>;reasoning_effort=<effort>` profile. Require Launcher profiles to match the exact expected model/effort in the owner-delivered activation or recovery prompt and require each metadata-read `role_task` to match the task ID independently read back by the external creator after dispatch, and require Orchestrator/Worker migration canaries to match the candidate resolved role configuration. Bind each Supervisor turn and result to its attempt number and configured attempt profile. Require each role to reread the live sources defined by the role contract.
- Treat eagerly exposed task-metadata tools as an incomplete catalog. Before classifying immutable task metadata unavailable, exhaust deferred tool discovery, invoke the discovered immutable metadata route in a metadata-only handshake, and require creator-side immutable task/turn-record read-back of the same task ID, model, and reasoning effort. Resolve `role_task` only from mutually equal task/session fields such as top-level `threadId`, metadata `thread_id`, and metadata `session_id`; record `turn_id` separately and never use it as a task ID. Before every populated role turn, independently reread the stable task/profile and put both in its envelope; on that exact turn the role rereads immutable metadata before action and records the new `metadata_turn`; after return the creator independently reads back that exact populated task/turn/profile and rejects the result before publication or transition on any mismatch. Self-report and eager-tool absence never prove identity or unavailability.
- Treat task archival, Git worktree removal, process release, and physical-path removal as separate cleanup facts. After archiving a short-lived role, use bounded external read-back to prove the task is no longer active, the exact Git registration is absent, no live process retains the exact Roundlet-owned worktree as its current directory, no unique work remains, and that physical worktree path is absent. Never kill a Codex or Node process to manufacture cleanup. Any missing inspection route, surviving worktree holder/registration/path, unique work, or ambiguous read-back keeps cleanup unverified and fails closed.
- Run only one issue through implementation and cleanup before selecting another issue.
- Keep core orchestration and safety rules in this file. Do not move them into a target repository's `AGENTS.md`.
- Read repository authority only from the root `AGENTS.md` on authoritative `origin/main`. Boolean authority may narrow Roundlet, never override stricter repository or platform policy.
- Fail closed when configured models, reasoning efforts, Supervisor attempt profiles, tools, GitHub permissions, merge method, repository authority, active contract identity, contract bundle, required filesystem canary evidence, or required state cannot be verified. Never substitute a model, effort, attempt profile, or contract silently.
- Treat GitHub CLI failures observed before GitHub is reachable as connectivity evidence, not credential rejection. When `gh` is required, require the model to request the narrowest scoped network escalation automatically; the skill cannot grant or assume network access. Never replace the request with browser authentication or browser automation. Keep bounded connectivity recovery out of Roundlet state transitions and owner input, and fail closed only when approval is explicitly denied, approval capability is unavailable, reachable GitHub rejects authentication, or bounded recovery proves the required connectivity unavailable.
- Use phase-aware lightweight observations only to prove that the last fully reconciled baseline is unchanged. Fingerprint the complete paginated scheduling graph and the exact active resources required by the phase; any change, omission, overflow, malformed value, due full audit, or action-ready state requires full live reconciliation in the same tick before reasoning or mutation. A fingerprint never authorizes a mutation.
- Never auto-expire, steal, or replace a lease. Recovery requires explicit owner direction after reconciliation.
- Couple a GitHub closing keyword only to the one active leaf that the pull request is intended to close. A negated phrase does not neutralize GitHub's keyword parser.
- Never rebase, force-push, bypass protection, destroy unique work, close an umbrella issue, or claim Supervisor PASS after the review limit.

## Activate through the Launcher

Use the Launcher prompt verbatim except for its explicit placeholders. The short-lived Launcher must:

1. Resolve the exact target repository, authoritative checkout, owner identity, and configuration.
2. Perform the capability, repository, GitHub, local-state, model, and authority preflight.
3. Reconcile any existing `.roundlet/lease.json`, `.roundlet/current.md`, `.roundlet/contracts/`, or `.roundlet/canary-evidence/` evidence; never take over automatically.
4. Reserve one stable run ID, complete the immutable task-metadata handshake, then run and clean up the exact advisory-state canary plus a metadata-verified short-lived configured Worker canary in a temporary linked worktree for file and Git-index mutation using that same run ID. After accepting and reading back the aggregate, independently verify archive, task liveness, exact-current-directory holders, Git registration, unique work, and physical-path removal. Stop before activation on any unproven surface or cleanup mismatch.
5. Create and read back the content-addressed activation contract bundle and manifest.
6. Create the configured long-lived Orchestrator task from the pinned bundle only through the immutable task-metadata handshake, require it to reread metadata on the populated bootstrap turn, repeat the advisory-state canary, and wait for its exact `ACTIVATION_READY` response.
7. Attach one heartbeat at configured `heartbeat.active_minutes` to that Orchestrator, send it the heartbeat identity, and archive the Launcher.

Do not attach the heartbeat to the Launcher. Do not proceed after a partial or ambiguous preflight.

## Run the outer loop

On activation and each heartbeat:

1. Resolve the effective active bundle from the immutable activation ID or valid legacy activation record plus the unique valid committed chain; treat lease/current active values only as mirrors. Read that effective bundle and compute the phase-aware observation vector defined in the operator guide, including the last completed filesystem-canary evidence-set digest, immutable accepted/failed evidence paths and result hashes, and every currently applicable live entry's task-metadata-verified execution profile plus task/host/route fingerprint. Fingerprint the installed skill and configuration separately without adopting them. When the vector is not a complete exact match for the last fully reconciled baseline, perform full GitHub, Git, Codex task, heartbeat, lease, contract, authority, and current-state reconciliation in the same tick before acting.
2. If a legacy run has no activation ID or valid legacy activation record, enter `LEGACY_CONTRACT_BOOTSTRAP_REQUIRED`; the bootstrap protocol produces and verifies that run's first canonical evidence set before any contract write, so its initial absence does not preempt bootstrap. A completed transition's immutable set remains historical evidence after its required clean short-lived resources are removed, but cannot authorize another transition. Before any new transition, build a fresh same-phase set for every applicable role; if that required set is incomplete, absent, stale for a live role, belongs to a different run/phase/task/host/route, or did not prove cleanup, enter `FILESYSTEM_CAPABILITY_BLOCKED` and make no Git/GitHub transition. Otherwise, if the installed fingerprint differs while cleanly `IDLE` with no active leaf, branch, worktree, Worker, pull request, or unresolved cleanup, enter `CONTRACT_ADOPTION_REQUIRED`. In every other phase enter `CONTRACT_MIGRATION_REQUIRED`. Make no repository transition until the allowlisted owner authorizes the exact candidate and the applicable protocol succeeds. If paused, stopped, awaiting owner input, blocked on repository authority, or already processing an issue, follow that state instead of scheduling.
3. If IDLE observation is unchanged, make no scheduling mutation and apply the configured no-op heartbeat backoff. Otherwise scan every open issue in the target repository, including issues created after activation.
4. Exclude umbrella, scheduling-blocked, ignored, non-actionable, dependency-blocked, and already-owned issues.
5. Rank all ready leaf candidates across umbrellas using the contract in the operator guide.
6. Read-only select exactly one issue and provision and read back one unpublished local `codex/` branch. On native Windows only, create and metadata-verify the intended persistent Worker at its host-owned task anchor, then create the isolated linked worktree as a separate writable descendant. On WSL, Linux, macOS, and every other non-Windows runtime, preserve the ordinary topology by creating and reading back the isolated worktree first and then creating and metadata-verifying the intended persistent Worker; no task anchor is required. After the applicable substrate and Worker identity exist, run the Orchestrator canary against the provisional branch and worktree, then run that Worker's worktree/index canary there. Make no source edit, commit, push, GitHub selection, or pull request until the complete same-phase aggregate is immutably stored and read back; only then record selection on GitHub and send implementation to that same Worker. Keep that Worker task through its lifecycle.
7. After the initial Worker handoff, comment on the issue, push the exact candidate SHA, and create a draft pull request.
8. Run bounded Supervisor/Worker review cycles and append every completed handoff to the pull request.
9. At a valid terminal review state, satisfy live merge gates, mark ready when authorized, merge with the configured merge method, verify or close the leaf issue, and perform ordered cleanup.
10. Select no new issue until cleanup proves the authoritative checkout, `main`, and `origin/main` are aligned and all issue-specific resources are removed.

Keep the heartbeat at `active_minutes` while work is active or an observation is incomplete. After consecutive unchanged IDLE observations, advance through `idle_noop_backoff_minutes`; while waiting for owner input, advance through `owner_input_noop_backoff_minutes`. Reset to the active interval on any change or direct owner instruction. A paused run has no heartbeat polling. Finishing an issue returns to IDLE and continues scheduling unless the owner explicitly requested stop-after-current.

## Bound the inner loop

- Rounds 1–3, when reached, are COMPLETE reviews. Any valid PASS ends review early.
- Rounds 4–10 are CONVERGING reviews. They focus on prior findings and the delta but may report a new blocking regression or missing evidence.
- Keep the review epoch, round, mode, and candidate SHA unchanged while Supervisor attempts advance through the configured ordered profiles. Accept only a valid `SUPERVISOR_RESULT` bound to all of them; never treat task failure text as findings or PASS, and never send an invalid attempt to the Worker.
- A Supervisor attempt that is invalid, fails, is cancelled, is inaccessible, is malformed, or reviews the wrong SHA does not consume a round. Advance only to the next configured attempt profile, without parsing display text to guess a policy or cybersecurity cause. After the configured attempt budget is exhausted, enter `NEEDS_OWNER_INPUT`.
- When round 10 returns findings, send them once to the same Worker for a final repair. Do not run round 11 and do not claim PASS. Record `REVIEW_LIMIT_REACHED_WORKER_FINALIZED`, then apply all normal checks and merge gates.
- An allowlisted owner scope change starts a new review epoch at round 1 COMPLETE.

## Stop safely

- `pause` takes effect at a safe checkpoint, pauses the heartbeat, and preserves the task, lease, branch, worktree, and current state for manual resume.
- `stop-after-current` finishes the active issue and cleanup, then stops the heartbeat, releases the lease, removes retained contract bundles, canary-evidence records, legacy bootstrap evidence, and migration records after final reconciliation, and archives the Orchestrator. If idle, stop immediately.
- A closed, ignored, or withdrawn active issue requires an explicit owner abort decision. Never silently abandon work or continue to the next issue while preserving the old issue's resources.
- Any unresolved ambiguity that could affect scope, dependency order, data safety, or an irreversible mutation enters `NEEDS_OWNER_INPUT` and stops global scheduling.
